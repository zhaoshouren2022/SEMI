# FAQ：常见问题

> 从标准各章节整理的高频疑问，答案都标注了出处，方便回查原文。

## 连接与状态

**Q: 设备能同时连接多个主机吗？**

A: HSMS 只要求设备至少能接受**一个**连接，不要求支持多主机并发（R1-3.1）。若设备已有一条主机连接，第二个连接尝试会被**立即终止**。特殊应用可以支持多主机，但多主机间的协调由设备定义（R1-3.2）。

**Q: 主机能连多个设备吗？**

A: 可以（R1-2.2）。一个主机可以同时有多条活动连接，每条连一台设备。Cell Controller 则"两头都当"：对工厂主机是设备，对设备是主机（R1-2.3）。

**Q: 为什么两个实体不能都配置成 Active 或都配置成 Passive？**

A: 都 Passive 没人发起连接；都 Active 没有监听方（A1-3.2）。必须一方主动一方被动（或一方用交替模式）。

**Q: 连接断掉后多久能重连？**

A: 遵守 T5 连接间隔：一次主动连接（成功或失败）之后，下一次主动连接至少间隔 T5（典型 10 秒，§9.2.1）。另外有些 TCP/IP 实现在断开后立即用相同端口重连会有问题，建议延迟约 2×MSL（典型 60 秒，A1-9）。

## 消息与会话

**Q: 数据消息能在 SELECTED 之外的状态发吗？**

A: 不能。SELECTED 是唯一允许数据交换的状态。在 NOT SELECTED 收到数据消息：通用服务回 Reject（ReasonCode=4），HSMS-SS 直接视为通信失败断开（§7.7 / E37.1 §7.5）。

**Q: 为什么 HSMS-SS 禁止用 Deselect 结束通信？**

A: Deselect 是"温和"结束，需要响应方状态与本地条件配合（可能返回"忙"）；SS 的目标是最简路径，用 Separate 一条消息立即结束、无响应、无条件（E37.1 §7.3 / §7.6）。

**Q: 两个实体同时发起 Select 会怎样？**

A: 通用服务允许（双方各自接受对方，§7.2.3）。HSMS-SS 则不允许：只有主动方才能发起 Select（E37.1 §7.1）。

**Q: Linktest 多久发一次？**

A: 标准不规定频率，由实现决定。典型做法是周期发送作为心跳（如每几秒到几十秒一次），T6 内无响应视为通信失败（§7.5）。

**Q: 什么是"无状态事务"？**

A: 控制事务（.req/.rsp）在状态机里没有"打开/未打开"状态：发起方等响应期间可能收到任何当时合法的消息（比如双方同时发起事务）。是否跟踪事务是纯实现细节（§9.3.2）。

## 参数与兼容

**Q: 为什么控制消息的 Session ID 是 0xFFFF？**

A: HSMS-SS 中 Select / Separate 用 0xFFFF 表示"整个连接 / 所有 Device ID"整体，而不是具体某个设备（E37.1 §7.1 / §7.6）。Linktest 在通用服务中也是 0xFFFF。

**Q: 254 字节限制是怎么回事？**

A: SECS-II 区分单块/多块消息，HSMS 不分块；但为兼容老 SECS-I 单块应用，发送单块消息时 HSMS 消息长度建议 ≤254 字节（10 头 + 244 文本，E37.1 §9.1）。

**Q: 可以自定义 PType / SType 消息吗？**

A: 可以，但只限**同厂商内部**通信（A1-10）。跨厂商接口使用自定义类型即不符合标准。若要用，建议使用"保留、未使用"范围内的值，避免与未来子标准冲突。

**Q: T8 和 SECS-I 的 T1 有什么区别？**

A: 都是"字符间隔"定时器，但 T8 只从**接收方**角度定义：一条消息内字节间的最大间隔（因为 TCP/IP 分包的间隔不完全受发送方控制，§9.2.3）。

## 场景设计

**Q: 我的设备有多个腔室，怎么用 Device ID？**

A: 每个腔室可以有自己的 Device ID 和会话（R1-1.1）。但如果腔室**共享**传输子系统等资源，不建议拆多个会话——共享资源没有自己的 Device ID，事件可能报错 Device ID（R1-1.2）。

**Q: 一台设备能不能既当主机又当设备？**

A: 可以，典型是 Cell Controller：对工厂主机是设备（被动），对下层设备是主机（主动），可以有多个连接（R1-2.3）。
