# 错误检测与定时器

> `E84` 的可靠性靠**互锁定时器（`Interlock Timer`）**兜底：主动设备与被动设备各自监控信号状态，超时即报错（§6.3）。本页给出所有定时器表与错误指示/恢复原则。

## 1. 错误指示（§6.3.1）

接口定义三类错误指示能力：

| 能力 | 含义 |
| --- | --- |
| **交接不可用**（`Handoff Unavailable`） | 通过 `HO_AVBL` 信号告知主动设备：被动设备（或被动 `OHS`）不可进行交接 |
| **急停请求**（`Emergency Stop`） | 通过 `ES` 信号请求主动设备（或主动 `Stocker`）立即停止 |
| **交接超时错误**（`Handoff Timeout Error`） | 互锁定时器超时（附录 A1 给出示例错误消息） |

## 2. 错误检测：互锁定时器（§6.3.2）

- `TAx` = 主动设备定时器，`TPx` = 被动设备定时器；所有定时器（除 `TD0`）范围 **1-999 秒**，设定值**用户可编程**（§6.3.2.1）。
- **延迟定时器**（§6.3.2.2）：`TD1` 指定一次连续交接中两个 `VALID` 之间的延迟（第一个交接 `VALID OFF` 到第二个交接 `VALID ON`）；`TD0` 定义主动设备 `CS_0/1 ON` 到 `VALID ON` 的时间（被动设备借此预测交接时序）。
- 定时器用于**检测超时**，不代表信号间的期望延迟；设备响应时间必须**快于**定时器超时（表 7/8 注 #2）。

### 2.1 主动设备定时器（表 7）

| 定时器 | 监控周期（信号状态） | 范围（秒） | 典型（秒） |
| --- | --- | --- | --- |
| `TA1` | `VALID ON` → `L_REQ ON` / `U_REQ ON` | 1-999 | 2 |
| `TA2` | `TR_REQ ON` → `READY ON` | 1-999 | 2 |
| `TA3` | `COMPT ON` → `READY OFF` | 1-999 | 2 |

### 2.2 被动设备定时器（表 8）

| 定时器 | 监控周期（信号状态） | 范围（秒） | 典型（秒） |
| --- | --- | --- | --- |
| `TP1` | `L_REQ ON` / `U_REQ ON` → `TR_REQ ON` | 1-999 | 2 |
| `TP2` | `READY ON` → `BUSY ON` | 1-999 | 2 |
| `TP3` | `BUSY ON` → 载具检测 / 载具取走 | 1-999 | 60 |
| `TP4` | `U_REQ OFF` / `L_REQ OFF` → `BUSY OFF` | 1-999 | 60 |
| `TP5` | `READY OFF` → `VALID OFF` | 1-999 | 2 |
| `TP6` | `VALID OFF` → `VALID ON`（连续交接） | 1-999 | 2 |

### 2.3 延迟定时器（表 9）

| 定时器 | 监控周期（信号状态） | 范围（秒） | 典型（秒） |
| --- | --- | --- | --- |
| `TD0` | `CS ON` → `VALID ON` | 0.1-0.2 | 0.1 |
| `TD1` | `VALID OFF` → `VALID ON`（连续交接） | 1-999 | 1 |

## 3. 错误恢复（§6.3.3）

- **错误恢复流程不在本规范定义**：可能需操作员协助和/或设备专有流程。
- 建议主动设备与被动设备都提供恢复流程（如**中止互锁序列并设为重启/完成**，§6.3.3.1）。
- 附录 A1 给出 `Interbay` 场景的恢复示例（见 [FAQ](faq.md)）。

## 4. 定时器超时示例错误消息（附录 A1-4.7）

**主动设备**（表 A1-8）：

| 定时器 | 示例消息 |
| --- | --- |
| `TA1` | `TA1 Timeout` – `L_REQ`/`U_REQ` 未在指定时间内 `ON`（`TA1 = xxx`） |
| `TA2` | `TA2 Timeout` – `READY` 未在指定时间内 `ON`（`TA2 = xxx`） |
| `TA3` | `TA3 Timeout` – `READY` 未在指定时间内 `OFF`（`TA3 = xxx`） |

**被动设备**（表 A1-9）：

| 定时器 | 示例消息 |
| --- | --- |
| `TP1` | `TP1 Timeout` – `TR_REQ` 未在指定时间内 `ON` |
| `TP2` | `TP2 Timeout` – `BUSY` 未在指定时间内 `ON` |
| `TP3` | `TP3 Timeout` – 载具未在指定时间内被检测/取走 |
| `TP4` | `TP4 Timeout` – `BUSY` 未在指定时间内 `OFF` |
| `TP5` | `TP5 Timeout` – `VALID` 未在指定时间内 `OFF` |
| `TP6` | `TP6 Timeout` – `VALID` 未在指定时间内 `ON` |

> `xxx` 为该定时器设定的秒数。错误消息须包含：定时器名、定时器描述、当前设定值（§A1-4.7.1）。

## 5. 定时器速记

| 定时器 | 谁监控 | 等什么 |
| --- | --- | --- |
| `TA1` | 主动 | 等被动方响应端口指定（`L/U_REQ`） |
| `TA2` | 主动 | 等被动方 `READY` |
| `TA3` | 主动 | 等被动方 `READY OFF` |
| `TP1` | 被动 | 等主动方 `TR_REQ` |
| `TP2` | 被动 | 等主动方 `BUSY` |
| `TP3` | 被动 | 等载具到位/取走（机械动作，典型 60 s） |
| `TP4` | 被动 | 等主动方完成物理交接（`BUSY OFF`，典型 60 s） |
| `TP5` | 被动 | 等主动方 `VALID OFF` 关闭握手 |
| `TP6` | 被动 | 等下一次 `VALID ON`（连续交接） |
| `TD0` | 主动 | `CS` 到 `VALID` 的短延迟（0.1-0.2 s） |
| `TD1` | 主动 | 连续交接中两次 `VALID` 的间隔 |

## 6. 错误时的信号状态（附录 A1-3.2.1）

实际工程中的重要约定（以 `OHS`-`Stocker` 为例）：

- **出错方保持 `BUSY ON`**：防止对方误动作导致二次事故（§A1-3.2.1.1.1）。
- **对方信号保持出错时状态**，仅 `READY` 转 `OFF`（§A1-3.2.1.1.2）。
- `Stocker` 侧出错时：`READY OFF`、`ES OFF`、`HO_AVBL OFF`（§A1-3.2.1.2.1）。
- `OHS` 侧出错时：只有 `BUSY ON`，其余信号全部 `OFF`（§A1-3.2.1.3）。

**自动恢复建议**（附录 A1-4.2/4.3）：主动车辆在 `BUSY ON` 之前出现的 `E84` 错误应能**自动恢复**（无需人工干预）；恢复方式为向 `Host` 发送 `Unsuccessful Transfer Complete` 命令，由 `Host` 指定备选位置（详见 [FAQ](faq.md)）。
